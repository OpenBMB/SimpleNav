# SimpleNAV 愿景与路线图

[返回中文 README](../../README_ZH.md)

## 项目愿景

SimpleNAV 的长期目标是构建一个面向视觉语言导航任务的类通用研究框架。它不绑定单一数据集、机器人平台、视觉语言骨干、动作空间或模拟器，而是通过稳定的中间协议和可扩展组件连接完整研究生命周期：

```text
数据获取与转换
  -> 统一导航表示
  -> 可组合模型开发
  -> 单域与多域训练
  -> 开环与闭环测评
  -> 结果、失败与部署反馈
  -> 新一轮数据和模型迭代
```

“类通用框架”并不表示所有任务必须使用完全相同的输入、动作和指标，而是要求不同任务能够在共享基础设施中保留自身语义，并通过显式 adapter 接入。

## 通用框架的五个维度

### 数据可扩展

- 适配空中、室内、地面、驾驶和真实平台导航数据。
- 支持单视角、多视角、视频、状态、地图和其他导航条件。
- 将坐标系、时间、动作和相机语义记录为可验证协议。
- 支持数据转换、轨迹增强、模拟器重渲染、统计和质量报告。
- 为受限数据发布 preparation manifest，而不是复制不可再分发内容。

### 模型可扩展

- 允许替换视觉语言骨干，而不重写数据和训练主流程。
- 允许组合历史选择、短期记忆、长期记忆、时空编码和世界模型。
- 支持连续 waypoint、离散导航动作和未来混合动作接口。
- 支持不同动作头、规划层和低层控制策略。
- 将模型能力与某个 benchmark 的特例实现分离。

### 训练可扩展

- 支持单数据集训练、多数据集 mixture 和跨域联合训练。
- 统一管理归一化、采样比例、状态动作契约和 checkpoint 元数据。
- 支持单机、多 GPU、多节点、断点恢复和可复现实验配置。
- 为未来的预训练、监督微调、偏好优化和在线适配保留清晰接口。

### 测评可扩展

- 使用 benchmark adapter 隔离输入格式、任务语义和指标定义。
- 使用 simulator backend 隔离 AirSim、Habitat、Unreal 和未来真实平台接口。
- 同时支持离线 action 检查、teacher forcing、开环和闭环评测。
- 统一记录 resolved config、运行计划、逐 episode 产物、失败和汇总指标。
- 允许新增 benchmark，而不修改公共 rollout 主循环。

### 生态可扩展

- 公开数据工具、模型卡、训练 recipe、评测模板和复现报告。
- 为数据、模型、benchmark 和部署模块建立稳定文档入口。
- 提供清晰的贡献边界、测试要求和第三方来源记录。
- 逐步形成可共享、可比较、可持续维护的 VLN 研究生态。

## 设计原则

### 共享基础设施，保留任务语义

统一的是存储、加载、训练、配置和产物组织；不统一或不能猜测的坐标、动作和指标由 adapter 明确转换。

### 通过接口扩展，而不是累积特例

新增数据集、模型或 benchmark 应实现对应 adapter 或组件，不应把任务名称和路径条件写入公共主循环。

### 复现是第一等产物

一次结果至少应关联：

- 代码提交与依赖环境；
- 数据版本、统计和处理 manifest；
- resolved training config；
- checkpoint 和模型卡；
- evaluation config、模拟器版本和资产摘要；
- 原始 episode 结果与汇总文件。

### 当前能力与未来目标分开陈述

路线图描述方向，不等同于当前支持状态。README 和发布说明必须区分“已实现”“已验证”“准备发布”和“长期研究目标”。

## 阶段路线图

### Release 01：建立可复现基础

目标：打通数据、模型、训练和评测的核心闭环。

- 统一 LeRobot v3 导航数据与动作契约。
- 提供数据转换、校验、修复、统计、历史索引和视觉 cache 工具。
- 提供 Qwen3.5-VL 导航模型路径。
- 提供单数据集和初始多数据集训练 recipe。
- 建立 AirSim、Habitat 和离线评测基础设施。
- 维护公开 checkpoint、模型卡、配置和 benchmark 结果。

### Release 02：形成模块化 VLN 开发框架

目标：降低新增数据、模型和 benchmark 的成本。

- 持续维护单仓内的 [`data_pipeline/`](../../data_pipeline/README_ZH.md) 数据转换、增强和模拟器采集工具链。
- 稳定 dataset adapter、model component 和 benchmark plugin 接口。
- 增加更多 VLM 骨干、记忆模块和动作头。
- 建立标准化模型卡、数据卡和复现 manifest。
- 提供便携的仿真环境准备、资产校验和 smoke test。
- 完善跨数据集混合训练和分域监控。

### Release 03：推进跨域通用导航

目标：从多个独立任务发展到共享表示和联合训练。

- 扩展空中、室内、地面、驾驶和真实平台数据。
- 研究跨平台状态与动作表示。
- 支持多域联合训练、域条件和任务条件模型。
- 系统评估未见场景、未见指令、未见平台和跨模拟器泛化。
- 探索世界模型、分层规划和在线记忆。

### 长期方向：通用具身导航与真实部署

- 构建能够理解多种导航指令、环境和平台的通用导航 VLA。
- 在保留任务动作语义的前提下，探索导航与操作数据的联合使用。
- 建立从模拟器、离线数据到真实平台的统一评测与部署接口。
- 完善实时控制、安全约束、故障恢复和持续学习能力。
- 形成由社区共同扩展的数据、模型和 benchmark 生态。

## 路线图评估方式

每个里程碑应由可验证产物定义，而不是仅以功能描述完成：

| 类型 | 最小可验证产物 |
| --- | --- |
| 新数据集 | adapter、语义说明、validation report、最小样本 |
| 新模型 | 配置、结构说明、checkpoint contract、smoke test |
| 新训练 recipe | resolved config、数据统计、日志和 checkpoint |
| 新 benchmark | 输入 adapter、运行配置、episode artifact、指标测试 |
| 新仿真后端 | 环境检查、版本记录、最小闭环运行和失败处理 |
| 新公开结果 | checkpoint、代码提交、配置、数据和原始 summary |
